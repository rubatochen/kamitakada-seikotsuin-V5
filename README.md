# 上高田整骨院 V5

一个面向小型整骨院 / 诊所的轻量级 Web 预约系统。

本项目基于 **Cloudflare Workers + D1 + Static Assets**
构建，不依赖传统服务器，适合个人开发者、小型诊所和社区型门店作为预约网站的基础模板使用。

> 本项目最初为「上高田整骨院」实际业务开发，同时保留了较清晰的目录结构，方便其他人根据自己的诊所信息、营业时间和业务规则进行修改。

------------------------------------------------------------------------

## ✨ 主要功能

### 顾客端

-   Web 在线预约
-   今天起最多预约未来 14 天
-   按日期查看可预约时间
-   开始时间支持分钟级选择
-   基本施术时间 25 分钟
-   可选择延长 10 / 20 / 30 分钟
-   根据延长时间自动计算系统占用时间
-   已预约、临时休息和不可预约时间自动排除
-   电话号码格式校验
-   预约成功页面
-   支持取消 / 修改预约时通过 LINE 或电话联系工作人员
-   中文 / 日文 / 英文界面
-   根据东京时间自动切换白天 / 夜间主题
-   白天使用「麻の葉」背景纹样
-   夜间使用「青海波」背景纹样
-   夜间可使用诊所门头照片作为 Hero 图片

### 管理端

-   管理员密码登录
-   查看指定日期的预约
-   预约与预约停止时间统一按时间顺序显示
-   手动预约
-   修改预约
-   取消预约
-   删除预约
-   临时休息时间设置 / 删除
-   休诊日设置 / 删除
-   每周营业时间设置
-   延长预约占用时间
-   中文 / 日本語后台切换
-   后台语言选择保存在浏览器中

### 数据与自动维护

-   Cloudflare D1 保存预约数据
-   预约支持实际占用时长
-   使用东京时间处理日期和预约时间
-   管理员 Session 使用 HttpOnly / Secure Cookie
-   Cloudflare Cron 每天自动清理一个月以前的历史预约

## ☁️ 部署方式

### 1. 创建 Cloudflare D1

在 Cloudflare 创建一个 D1 Database。

然后执行：

``` bash
npx wrangler d1 execute <DATABASE_NAME> --remote --file=schema.sql
```

如果使用已有数据库并且只是升级预约时长字段，再根据实际数据库状态执行：

``` bash
npx wrangler d1 execute <DATABASE_NAME> --remote --file=migration-add-duration-minutes.sql
```

**注意：已经执行过 migration 后不要重复执行。**

------------------------------------------------------------------------

### 2. 配置 D1 Binding

`wrangler.toml` 中需要配置：

``` toml
[[d1_databases]]
binding = "DB"
database_name = "your-database-name"
database_id = "your-database-id"
```

其中：

-   `binding = "DB"` 必须和代码中的 `env.DB` 对应
-   `database_name` 修改成自己的 D1 名称
-   `database_id` 修改成自己的 D1 ID

------------------------------------------------------------------------

### 3. 配置 Static Assets

当前 Worker 结构使用：

``` toml
main = "./dist/worker/index.js"

[assets]
directory = "./site"
binding = "ASSETS"
```

Worker 会：

-   `/api/*` → 调用后端 API
-   其他请求 → 从 `site/` 提供静态文件

------------------------------------------------------------------------

### 4. 配置管理员密码

不要把管理员密码直接写进代码。

在 Cloudflare 中设置 Runtime Secret：

``` text
ADMIN_PASSWORD
```

然后重新部署。

## ⏰ 自动清理历史预约

项目包含 Cloudflare Cron：

``` toml
[triggers]
crons = ["0 18 * * *"]
```

Cloudflare Cron 使用 UTC，因此：

``` text
18:00 UTC
↓
03:00 JST（日本时间，次日）
```

定时任务会调用 Worker 的 `scheduled()`，删除一个月以前的预约记录。

当前逻辑相当于：

``` sql
DELETE FROM appointments
WHERE date < ?
```

其中 `?` 是根据东京时间计算得到的一个月前日期。

如果你不需要自动清理，可以删除 `[triggers]` 配置以及 Worker 中对应的
`scheduled()` 逻辑。

## 🎨 设计思路

本项目没有采用典型的「现代 SaaS 医疗后台」风格，而是更偏向：

-   温暖
-   安静
-   社区型
-   传统日式
-   少装饰
-   信息密度适中
-   手机优先

视觉主题：

``` text
白天
米色 + 橘红 + 金黄色
麻の葉

夜间
黑色 + 墨绿色 + 绿色
青海波
```

背景纹样只作为非常淡的暗纹使用，避免影响文字阅读。

如果套用到其他诊所，可以直接更换颜色、图片和纹样，而不必改变预约系统的核心逻辑。

## 🔐 安全说明

这是一个**小型诊所自用系统**，设计目标是简单、实用、低维护。

已经包含：

-   管理员密码认证
-   Session Cookie
-   HttpOnly
-   Secure
-   SameSite
-   管理 API 鉴权
-   基础输入校验
-   预约冲突检查
-   D1 数据库

但它并不是企业级医疗信息系统。

如果用于：

-   大型医疗机构
-   大量用户
-   高敏感医疗数据
-   多管理员、多角色权限
-   在线支付
-   严格审计要求

建议在此基础上进一步增加权限管理、审计日志、数据保护、备份策略等。

------------------------------------------------------------------------

## 📌 关于医疗数据

预约系统会保存姓名、电话等预约信息。

如果你把本项目用于自己的诊所，请根据所在国家 /
地区的法律法规和自己的业务需求处理个人信息。

尤其不要因为「只是一个预约网站」就把管理员密码、API 密钥或其他 Secret
提交到 Git。
